# Bug 6 — `SubstitutionDefinition` fails on regex-metacharacter delimiters

**File:** [`SubstitutionDefinition.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/utils/SubstitutionDefinition.java#L22-L25) [^src-1]
**Severity:** MEDIUM (breaks valid Vim substitution delimiters)

## Description

`SubstitutionDefinition` allows any non-alphanumeric character as the delimiter, then splits the command with an unquoted regex:

```java
String delim = "" + def.charAt(def.indexOf('s') + 1);
String[] fields = def.split("(?<!\\\\)" + delim, -1);
```

Because `delim` is concatenated directly into the regex:
- `:s|foo|bar|` builds `"(?<!\\)|"`, splitting on every empty boundary instead of `|`.
- `:s.foo.bar.` builds `"(?<!\\)."`, splitting on every character.
- `:s+foo+bar+`, `:s*foo*bar*`, `:s?foo?bar?`, `:s(foo(bar(`, `:s[foo[bar[` throw `PatternSyntaxException`.

## Impact

- Standard Vim alternative delimiters (`|`, `+`, `.`, `?`, etc., commonly used when patterns contain `/` or `#`) fail or produce nonsensical substitutions.

## Suggested fix

- Wrap the delimiter with `Pattern.quote(delim)`:
  ```java
  String[] fields = def.split("(?<!\\\\)" + Pattern.quote(delim), -1);
  ```
- Add unit tests in `CommandLineTests.java` for `|`, `.`, `+`, `?`, and `[` delimiters.

**Status:** OPEN.
