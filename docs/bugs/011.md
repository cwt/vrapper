# Bug 11 — Listener and `WeakHashMap` reference leaks on editor close and `MultiPageEditorPart`

**Files:** [`VimInputInterceptorFactory.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/interceptor/VimInputInterceptorFactory.java#L269-L282) [^src-1], [`InputInterceptorManager.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/interceptor/InputInterceptorManager.java#L248-L293) [^src-2], [`EclipseUserInterfaceService.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipseUserInterfaceService.java#L44-L121) [^src-3]
**Severity:** MEDIUM (retained closed editors, documents, and `EditorAdaptor` instances across editing sessions)

## Description

Three listener/lifecycle leaks occur when editors are closed or `partInputChanged` fires:

1. **`LinkedModeHandler` not unregistered:** `VimInputInterceptorFactory.createInterceptor()` calls `LinkedModeHandler.registerListener(textViewer.getDocument(), linkedModeHandler)` and stores it via `interceptor.setLinkedModeHandler(...)`, but `InputInterceptorManager.partClosed()` never calls `LinkedModeHandler.unregisterListener(...)`.
2. **`ContentAssistModeHandler` not stored or removed:** `VimInputInterceptorFactory` adds `new ContentAssistModeHandler(editorAdaptor)` via `contentAssistant.addCompletionListener(...)` without retaining a reference or removing it in `partClosed()`.
3. **`PartChangeListener` leak on `MultiPageEditorPart` inner editors:** `EclipseUserInterfaceService` registers `PartChangeListener` on `IPartService`, and `partClosed(IWorkbenchPart arg0)` checks `if (arg0 == editor)`. For multipage editors (such as XML/`pom.xml` or PDE manifest editors), `editor` is the inner `AbstractTextEditor`, while `IPartService` passes the outer `MultiPageEditorPart`, so `arg0 == editor` is always `false` and the listener is never removed.
4. **Strong value-to-key cycle in `WeakHashMap`:** `InputInterceptorManager.interceptors` and `toplevelEditorInfo` are `WeakHashMap<IWorkbenchPart, ...>`, but `InputInterceptor` holds strong references back to the `IEditorPart` key via `EditorInfo` and `EclipsePlatform.underlyingEditor`, preventing weak collection if `partClosed` is skipped.

## Impact

- Closed `ITextViewer`, `IDocument`, `EditorAdaptor`, and `AbstractTextEditor` instances accumulate in memory across long Eclipse sessions, especially when opening/closing multipage editors.

## Resolution

Fixed all four listener/lifecycle and `WeakHashMap` reference-cycle leaks across the Eclipse integration layer:

1. Added `getContentAssistModeHandler()` / `setContentAssistModeHandler(ContentAssistModeHandler)` and `dispose()` to [`InputInterceptor.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/interceptor/InputInterceptor.java) and [`VimInputInterceptorFactory.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/interceptor/VimInputInterceptorFactory.java), retaining created `ContentAssistModeHandler` instances on the interceptor.
2. Updated [`LinkedModeHandler.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/interceptor/LinkedModeHandler.java) and [`ContentAssistModeHandler.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/interceptor/ContentAssistModeHandler.java) to track registered `IDocument`/`LinkedModeModel` via `WeakReference` and detach `EditorAdaptor` references on teardown, preventing queued `asyncExec` callbacks or retained listener references from holding closed editors.
3. Updated [`InputInterceptorManager.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/interceptor/InputInterceptorManager.java) (`partClosed()`) to fall back to `platform.getUnderlyingSourceViewer()` if `AbstractTextEditor.getSourceViewer()` is already `null`, unregister `LinkedModeHandler` and `ContentAssistModeHandler`, remove `IOperationHistoryListener`, call `platform.dispose()` and `interceptor.dispose()` in a `finally` block, and clean up/dispose child `EditorInfo` entries. Also guarded disposed widgets / null documents in [`EclipseCursorAndSelection.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipseCursorAndSelection.java) (`uninstallHooks()`) and cleared interceptor references on widget disposal in [`CommandLineUIFactory.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/ui/CommandLineUIFactory.java) plus window part listeners on `windowClosed()` in [`VrapperPlugin.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/activator/VrapperPlugin.java).
4. Retained `PartChangeListener` and `WeakReference<IPartService>` in [`EclipseUserInterfaceService.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipseUserInterfaceService.java) with a `dispose()` method invoked from `EclipsePlatform.dispose()` (as well as `PartChangeListener.partClosed()`), ensuring listeners registered on inner `MultiPageEditorPart` pages are always removed on close.
5. Broke strong value-to-key cycles across all `WeakHashMap` tables (`interceptors`, `toplevelEditorInfo`, `bufferAndTabServices`, `reservedBufferIdMapping`) by storing `WeakReference` editor/window/reference handles in [`EditorInfo.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/interceptor/EditorInfo.java) (using `WeakHashMap` for `childEditors`), [`BufferInfo.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/interceptor/BufferInfo.java), [`EclipseBufferAndTabService.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipseBufferAndTabService.java), [`EclipsePlatform.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipsePlatform.java), [`EclipseFileService.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipseFileService.java), [`EclipseHighlightingService.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipseHighlightingService.java), and [`AbstractTextEditorSettings.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/AbstractTextEditorSettings.java).

Verified compilation and full reactor build via `mvn -B clean verify --file pom.xml` across all 41 modules (`322` run, `0` failures, `0` errors, `2` pre-existing `@Ignore` skipped in `core.tests`; `6/6` in `surround.tests`; note that `tests/` does not include an automated SWT workbench UI test harness for `net.sourceforge.vrapper.eclipse`).

**Status:** FIXED.
