# Bug 3 — `s/\%V` substitution replaces outside visual-block columns on multi-line selections

**File:** [`SubstitutionOperation.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/commands/SubstitutionOperation.java#L53-L124) [^src-1]
**Upstream Issue:** [vrapper/vrapper#848](https://github.com/vrapper/vrapper/issues/848)
**Severity:** HIGH (corrupts text outside the selected visual block)

## Description

When executing `:'<,'>s/\%Vfoo/bar/g`, `SubstitutionOperation.execute()` loops over `i = range.getStartLine() .. endLine` and calls `performReplace(line, subDef.find, ...)`:

```java
int start = line.getBeginOffset();
int end = line.getEndOffset();
if (find.contains("\\%V")) {
    find = find.replaceAll("\\\\%V", "");
    Selection selection = editorAdaptor.getSelection();
    if (selection != null) {
        start = selection.getLeftBound().getModelOffset();
        end = selection.getRightBound().getModelOffset();
    }
}
```

For a multi-line `BlockWiseSelection` spanning lines `L1..LN`, `selection.getLeftBound()` is `(L1, colStart)` and `selection.getRightBound()` is `(LN, colEnd)` [^src-2]. On the very first iteration (`i = L1`), `searchAndReplace.replace(start, end, ...)` runs across the **entire contiguous offset range `[L1:colStart, LN:colEnd]`**, replacing matches across all columns of lines `L2..LN-1` (and before `colEnd` on `LN` / after `colStart` on `L1`).

## Impact

- `:s/\%V.../g` on a visual-block selection replaces matches outside the selected box on subsequent lines, matching the exact failure reported in upstream `#848`.
- On multi-line characterwise visual selections with `:s/\%V.../g`, `performReplace` runs the full multi-line range on iteration 1 and repeats against stale bounds on remaining iterations.

## Suggested fix

- Clamp `[start, end]` to the current `line` (`[line.getBeginOffset(), line.getEndOffset()]`).
- When `selection` is a `BlockWiseSelection` (checking `ContentType.TEXT_RECTANGLE`), compute the `TextBlock` via `BlockWiseSelection.getTextBlock(...)` and resolve the current line's visual `[startVisualOffset, endVisualOffset]` bounds using `CursorService.getPositionByVisualOffset(...)` (skipping lines shorter than `startVisualOffset`, and adjusting `end` when `line` ends before `endVisualOffset`).
- Add unit tests in `CommandLineTests.java` covering `\%V` in characterwise and blockwise visual modes.

**Status:** OPEN.
