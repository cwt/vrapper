# Bug 5 — `EclipseCursorAndSelection.getPositionByVisualOffset()` overflow, `/ 0`, and infinite-loop hazards

**File:** [`EclipseCursorAndSelection.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipseCursorAndSelection.java#L880-L921) [^src-1]
**Severity:** HIGH (can throw `IllegalArgumentException` / `ArithmeticException` or hang the SWT UI thread)

## Description

`getPositionByVisualOffset(int lineNo, int visualOffset)` (used by visual-block yank, delete, change, paste, `I`, and `A`) has multiple coordinate and loop bugs:

1. **Folded lines & model vs. widget mismatch (lines 885–896):** `lineOffset = converter.modelOffset2WidgetOffset(region.getOffset())` returns `-1` if `lineNo` is folded, and `lineOffset + region.getLength() - 1` adds a *model* line length to a *widget* offset. Passing `-1` or an out-of-range index to `tw.getTextBounds(...)` throws `IllegalArgumentException`.
2. **Horizontal scroll / zero-width crash (line 904):**
   ```java
   int offset = lineOffset + (region.getLength() * visualOffset) / lineBounds.width;
   ```
   - Uses `visualOffset` (which includes `tw.getHorizontalPixel()`) instead of `relVOffset` (`visualOffset - tw.getHorizontalPixel()`), causing `offset` to overshoot the line end or buffer end when scrolled horizontally.
   - Does not check `lineBounds.width == 0`, causing `ArithmeticException: / by zero`.
3. **Unbounded `while` loop (lines 909–915):**
   ```java
   while (!(rect = tw.getTextBounds(offset, offset)).contains(relVOffset, rect.y)) {
       if (rect.x > relVOffset) {
           --offset;
       } else {
           ++offset;
       }
   }
   ```
   If `relVOffset` falls in a pixel gap or between non-monotonic glyph bounds (tabs, kerning, combining/zero-width characters, RTL text), `offset` can oscillate indefinitely (hanging Eclipse's UI thread) or walk outside `[lineOffset, lineEndOffset]`.

## Impact

- Visual-block operations on horizontally scrolled lines, folded regions, or lines with zero-width/non-monotonic glyphs can crash with `IllegalArgumentException` / `ArithmeticException` or freeze the Eclipse UI thread.

## Suggested fix

- Convert `lineOffset` safely (return `null` if `< 0`), compute `widgetLine = converter.modelLine2WidgetLine(lineNo)`, and obtain the exact widget line range `[lineStart, lineEnd]` from `tw.getOffsetAtLine(widgetLine)` and `tw.getLine(widgetLine).length()`.
- Guard `lineBounds.width <= 0`, compute the initial guess with `relVOffset - lineBounds.x`, clamp `offset` to `[lineStart, lineEnd - 1]`, and use binary search (or bound iterations to line length and exit cleanly if bounds stop converging).
