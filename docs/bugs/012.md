# Bug 12 — Missing null checks in `EclipsePlatform` undo wrapper and `CLabel.shortenText`

**Files:** [`EclipsePlatform.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipsePlatform.java#L91-L100) [^src-1], [`CLabel.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/ui/CLabel.java#L25-L39) [^src-2]
**Upstream Issue:** Related to [vrapper/vrapper#828](https://github.com/vrapper/vrapper/issues/828)
**Severity:** LOW (defensive null-safety hazards)

## Description

1. **Null `IUndoManager` delegate in `EclipsePlatform` (lines 91–100):**
   ```java
   if (sourceViewer instanceof ITextViewerExtension6) {
       final IUndoManager delegate = ((ITextViewerExtension6) sourceViewer).getUndoManager();
       final EclipseHistoryService manager = new EclipseHistoryService(sourceViewer, delegate);
       sourceViewer.setUndoManager(manager);
       this.historyService = manager;
   }
   ```
   If `sourceViewer.getUndoManager()` returns `null` (for example in custom or structured text viewers), `EclipseHistoryService` wraps `null` and subsequently throws `NullPointerException` on `undo()`, `redo()`, or `beginCompoundChange()`.
2. **Null `modeName` in `CLabel.shortenText()` (lines 25–39):**
   `shortenText(GC gc, String t, int width)` assigns `String shorter = modeName;` and immediately calls `gc.textExtent(shorter)`. If `setText(null)` is ever invoked or `shortenText` runs before `modeName` is initialized, SWT throws `IllegalArgumentException: Argument cannot be null`.

## Impact

- Potential `NullPointerException` on undo/redo in viewers without an initialized `IUndoManager`, and potential SWT `IllegalArgumentException` if `modeName` is `null`.

## Suggested fix

- Check `delegate != null` in `EclipsePlatform` before constructing `EclipseHistoryService` (falling back to `DummyHistoryService` when `null`).
- Guard `modeName == null` in `CLabel.shortenText()` (fall back to `t` or `""`).

**Status:** OPEN.
