# Bug 9 — `BlockwiseVisualMode` skips shorter lines on change and mishandles empty lines with `$`

**Files:** [`SelectionBasedTextOperationCommand.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/commands/SelectionBasedTextOperationCommand.java#L110-L138) [^src-1], [`BlockWiseSelection.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/commands/BlockWiseSelection.java#L114-L122) [^src-2]
**Upstream Issue:** [vrapper/vrapper#663](https://github.com/vrapper/vrapper/issues/663)
**Severity:** MEDIUM (incomplete block edits / wrong block width calculation)

## Description

1. **Short lines skipped in `BlockwiseRepeatCommand.doIt()`:**
   When a block selection starts past the length of an intermediate line (for example, starting at column 11 on line 1, pressing `<C-v>$` across a shorter 10-char line 2, and pressing `c`), `cursorService.getPositionByVisualOffset(line, block.startVisualOffset)` returns `null` for line 2. Because `if (runStart != null)` guards execution, line 2 is skipped completely (whereas Vim appends the replacement text when `$` / `stickToEOL` was used, or pads/inserts depending on command).
2. **Empty-line offset underflow in `BlockWiseSelection.getTextBlock()` (lines 114–122):**
   ```java
   if (cursorService.shouldStickToEOL()) {
       result.endVisualOffset = result.startVisualOffset;
       for (int i = result.startLine; i <= result.endLine; i++) {
           final LineInformation line = textContent.getLineInformation(i);
           final int lastOfs = cursorService.getVisualOffset(cursorService
                   .shiftPositionForModelOffset(line.getEndOffset(), -1, false));
           result.endVisualOffset = Math.max(result.endVisualOffset, lastOfs);
       }
   }
   ```
   When `line.getLength() == 0`, `line.getEndOffset() == line.getBeginOffset()`, so `shiftPositionForModelOffset(..., -1, false)` steps backwards onto the **previous line's** end character and uses that line's visual width instead of `0`.

## Impact

- Visual-block `c` after `<C-v>$` silently omits shorter lines in the block.
- Visual-block `$` spanning an empty line can compute `endVisualOffset` from the wrong line.

## Resolution

Fixed visual-block boundary and empty/short-line handling across [`BlockWiseSelection.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/commands/BlockWiseSelection.java#L106-L185) [^src-2], [`BlockWiseSelectionArea.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/utils/BlockWiseSelectionArea.java#L37-L60) [^src-3], [`SelectionBasedTextOperationCommand.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/commands/SelectionBasedTextOperationCommand.java#L81-L246) [^src-1], and [`BlockwiseVisualMode.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/modes/BlockwiseVisualMode.java#L149-L163) [^src-4]:

- Avoided shifting `-1` onto the previous line in `BlockWiseSelection.getTextBlock()` when `line.getLength() == 0` under `stickToEOL`, and added `getTextBlock(..., boolean stickToEOL)` so `BlockwiseRepeatCommand` and `.` repetition preserve `$` (`isUntilEOL`) across all lines in the block (and treat EOF consistently under `selection=inclusive`).
- Added `BlockWiseSelection.getPositionOrEOLByVisualOffset()` so lines ending exactly at `startVisualOffset` (e.g. a 10-char line when a block starts at column 11) participate in visual-block `c`, `I`, and `BlockWiseSelectionArea`, matching Vim while leaving strictly shorter lines untouched.
- Guarded `lineInfo.getLength() == 0`, clamped `runEnd` to `lineInfo.getEndOffset()`, and positioned the cursor at `runStart` on the first block line so empty lines in visual-block `d`/`c` never delete newlines or insert on the wrong line.
- Updated `TestCursorAndSelection.getPositionByVisualOffset()` to return `null` when out of line bounds matching `EclipseCursorAndSelection`, and added `BlockwiseVisualModeTests.test_shorterAndEmptyLinesWithDollarAndChange`. Verified via `mvn -B clean verify --file pom.xml` (`322` run, `0` failures, `0` errors, `2` pre-existing `@Ignore` skipped in `core.tests`; `6/6` in `surround.tests`).

**Status:** FIXED.
