# Bug 7 — Nested `if`/`endif`, `func`/`endfunc`, and `try`/`endtry` fail in `.vrapperrc`/`.vimrc`

**File:** [`DefaultEditorAdaptor.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/DefaultEditorAdaptor.java#L325-L351) [^src-1]
**Upstream Issue:** [vrapper/vrapper#878](https://github.com/vrapper/vrapper/issues/878)
**Severity:** MEDIUM (aborts `.vrapperrc` / `.vimrc` parsing on nested Vimscript conditionals)

## Description

`DefaultEditorAdaptor.sourceConfigurationFile()` attempts to skip unsupported Vimscript `if`..`endif`, `func`..`endfunc`, and `try`..`endtry` blocks:

```java
if(trimmed.startsWith("if")) {
    //skip all conditional statements
    while((line = reader.readLine()) != null) {
        if(line.trim().toLowerCase().startsWith("endif")) {
            break;
        }
    }
    continue; //skip "endif" line
}
```

1. **No nesting depth counter:** An inner `endif` breaks out of the outer `while` loop, leaving the outer `endif` to be parsed by `CommandLineParser`, which errors with `Not an editor command: endif` and aborts parsing the remaining lines of the file. The same applies to nested `func`/`endfunc` and `try`/`endtry` (as well as `en`/`end` abbreviations or `endfunction`).
2. **Missing word-boundary checks:** `trimmed.startsWith("if")`, `trimmed.startsWith("func")`, and `trimmed.startsWith("try")` match any line whose prefix happens to start with those letters.

## Impact

- Shared `.vimrc`/`.vrapperrc` configurations containing nested `if ... endif` blocks fail to finish loading.

## Resolution

Updated `DefaultEditorAdaptor.sourceConfigurationFile` with `SkippedBlock` stack tracking ([`DefaultEditorAdaptor.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/DefaultEditorAdaptor.java#L298-L401)) [^src-1]:

- Uses word-boundary, locale-invariant patterns for `if`/`en[dif]`, `fu[nction]`/`endf[unction]`, and `try`/`endt[ry]`, after skipping comment lines (`"`) and stripping optional leading `:`.
- Tracks nested and mixed blocks (e.g. `func` inside `if`, nested `if`, nested `try`) with a `Deque<SkippedBlock>` stack while keeping `lineNr` accurate.
- Added `VrapperRCTests.testNestedUnsupportedBlocksInSourceConfigurationFile` ([`VrapperRCTests.java`](../../tests/net.sourceforge.vrapper.core.tests/src/net/sourceforge/vrapper/core/tests/cases/VrapperRCTests.java#L57-L100)). Verified via `mvn -B clean verify --file pom.xml` (`320` run, `0` failures, `0` errors, `2` pre-existing `@Ignore` skipped in `core.tests`; `6/6` in `surround.tests`).

**Status:** FIXED.
