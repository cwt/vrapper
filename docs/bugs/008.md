# Bug 8 — `SelectTextObjectCommand` exits `BlockwiseVisualMode` into `VisualMode`

**Files:** [`SelectTextObjectCommand.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/commands/SelectTextObjectCommand.java#L44-L81) [^src-1], [`AbstractVisualMode.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/modes/AbstractVisualMode.java#L211-L212) [^src-2]
**Upstream Issue:** [vrapper/vrapper#858](https://github.com/vrapper/vrapper/issues/858)
**Severity:** MEDIUM (breaks visual-block workflow with text objects)

## Description

`BlockwiseVisualMode` inherits `VisualTextObjectState` [^src-3] from `AbstractVisualMode`, which maps text objects (`iw`, `aw`, `i"`, `i(`, etc.) to `SelectTextObjectCommand`. In `SelectTextObjectCommand.execute()`:

```java
case TEXT:
    String selectionOption = editorAdaptor.getConfiguration().get(Options.SELECTION);
    boolean isInclusive = Selection.INCLUSIVE.equals(selectionOption);
    selection = new SimpleSelection(editorAdaptor.getCursorService(), isInclusive, region);
    newMode = VisualMode.NAME;
    break;
...
editorAdaptor.changeMode(newMode, AbstractVisualMode.FIX_SELECTION_HINT);
```

Regardless of whether the editor is currently in `BlockwiseVisualMode`, `SelectTextObjectCommand` creates a `SimpleSelection` and switches to `VisualMode.NAME`.

## Impact

- Sequences like `<C-v>iw` leave visual-block mode and turn into characterwise visual selection, preventing subsequent `j`/`k` block extension across columns.

## Resolution

Updated `SelectTextObjectCommand.execute` ([`SelectTextObjectCommand.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/commands/SelectTextObjectCommand.java#L29-L97)) [^src-1] so that when `editorAdaptor.getCurrentModeName()` is `BlockwiseVisualMode.NAME` and the text object returns `ContentType.TEXT`, it keeps `BlockwiseVisualMode.NAME` with a `BlockWiseSelection` built from the inclusive endpoints of `region` (and accounts for `BlockWiseSelection`'s exclusive stored right bound when expanding chained `DelimitedTextObject` calls such as `i{i{`). Added `BlockwiseVisualModeTests.test_textObjectsPreserveBlockwiseMode` ([`BlockwiseVisualModeTests.java`](../../tests/net.sourceforge.vrapper.core.tests/src/net/sourceforge/vrapper/core/tests/cases/BlockwiseVisualModeTests.java#L472-L491)). Verified via `mvn -B clean verify --file pom.xml` (`321` run, `0` failures, `0` errors, `2` pre-existing `@Ignore` skipped in `core.tests`; `6/6` in `surround.tests`).

**Status:** FIXED.
