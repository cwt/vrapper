# Bug 2 — `InsertMode` wipes `mOnLeaveHint`, `count`, and `repetitionCommand` on `RESUME_ON_MODE_ENTER`

**Files:** [`InsertMode.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/modes/InsertMode.java#L119-L198) [^src-1], [`EclipseHistoryService.java`](../../plugins/net.sourceforge.vrapper.eclipse/src/net/sourceforge/vrapper/eclipse/platform/EclipseHistoryService.java#L31-L42) [^src-2]
**Severity:** HIGH (lost block edits + permanently locked undo compound change)

## Description

When leaving `InsertMode` via `InsertMode.RESUME_ON_MODE_ENTER` (for example, when Eclipse Content Assist opens via `ContentAssistModeHandler` [^src-3], `<C-x>` triggers `InsertExpandMode` [^src-4], `<A-o>` opens `CommandLineMode`, or `<C-r>` opens `PasteRegisterMode`), `InsertMode.leaveMode()` sets `resumeOnEnter = true` and returns early.

Upon returning to `InsertMode.enterMode(ModeSwitchHint... args)`, `initMode` evaluates to `false`, **yet lines 133–135 unconditionally execute**:

```java
boolean initMode = !resumeOnEnter;
resumeOnEnter = false;
...
count = 1;
repetitionCommand = null;
mOnLeaveHint = null;
```

Only `PasteRegisterMode` re-passes `mOnLeaveHint`; `ContentAssistModeHandler`, `InsertExpandMode`, and `<A-o>` do not, and none of them preserve `count` or `repetitionCommand`.

## Impact

- If Content Assist, `<C-x>`, or `<A-o>` runs during visual-block `I`, `A`, `c`, `C`, or `s`:
  1. `mOnLeaveHint` (`BlockwiseRepeatInsertCommand` / `BlockwiseRepeatCommand`) is discarded, so the edit is **not** replicated across the remaining lines in the block.
  2. `EclipseHistoryService` was locked under `"block-action"` when entering block insert/change; because `mOnLeaveHint` is never run on `<Esc>`, `history.unlock("block-action")` and `history.endCompoundChange()` are **never called**, permanently locking compound undo changes in that editor.
- Counted inserts (e.g., `3i`) and `.` repetition prefixes (`o`/`O`/`I`/`A`) are also lost if autocomplete triggers before `<Esc>`.

## Suggested fix

- Move `count = 1; repetitionCommand = null; mOnLeaveHint = null;` inside `if (initMode) { ... }` in `InsertMode.enterMode()`, and only overwrite them if new hints explicitly supply replacements.
- Add a unit test verifying `mOnLeaveHint` and `count` survive a `RESUME_ON_MODE_ENTER` round-trip.

**Status:** OPEN.
