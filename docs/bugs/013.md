# Bug 13 — Core unit tests fail on JDK 25 due to ByteBuddy `1.14.11` / Mockito `5.10.0`

**Files:** [`net.sourceforge.vrapper.releng.target.target`](../../releng/net.sourceforge.vrapper.releng.target/net.sourceforge.vrapper.releng.target.target#L165-L197) [^src-1], [`net.sourceforge.vrapper.releng.target.tpd`](../../releng/net.sourceforge.vrapper.releng.target/net.sourceforge.vrapper.releng.target.tpd#L96-L127) [^src-2]
**Severity:** HIGH (blocks `mvn verify` test execution on JDK 25)

## Description

Running `mvn -B verify --file pom.xml` on JDK 25 (`25.0.5.0.3`, class file version 69) fails in `net.sourceforge.vrapper.core.tests` (`Tests run: 309, Failures: 17, Errors: 258, Skipped: 2`) and aborts before `net.sourceforge.vrapper.plugin.surround.tests` and `releng` packaging.

Every Mockito-using test class fails during `VimTestCase.initMocks()` with:

```text
org.mockito.exceptions.base.MockitoException:
Mockito cannot mock this class: class net.sourceforge.vrapper.testutil.TestCursorAndSelection.
...
Caused by: java.lang.IllegalArgumentException: Java 25 (69) is not supported by the current version of Byte Buddy which officially supports Java 22 (66) - update Byte Buddy or set net.bytebuddy.experimental as a VM property
```

The target definition currently pins `net.bytebuddy:byte-buddy` / `byte-buddy-agent` `1.14.11` and `org.mockito:mockito-core` / `mockito-junit-jupiter` `5.10.0` [^src-1].

## Impact

- `mvn clean verify` cannot execute the test suite or produce the update site on JDK 25 unless tests are skipped (`-DskipTests`) or ByteBuddy/Mockito are upgraded.
- Non-Mockito unit tests (`KeyMapTests`, `PatternUtilsTests`, `SimpleKeyStrokeTests`, `StateAndTransitionTests`, `UtilityTests`) pass (`32/32`), while all 14 Mockito-based test classes error/fail in setup.

## Suggested fix

- Upgrade `byte-buddy` / `byte-buddy-agent` (to a release with Java 25 / class version 69 support, e.g., `1.17.x+`) and compatible `mockito-core` / `mockito-junit-jupiter` in both `net.sourceforge.vrapper.releng.target.tpd` and `net.sourceforge.vrapper.releng.target.target` (plus check `pom.xml` `<java.version>` / `Bundle-RequiredExecutionEnvironment` alignment if targeting JDK 25 directly).

**Status:** OPEN.
