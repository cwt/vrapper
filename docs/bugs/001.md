# Bug 1 — CommandLineParser splits `" | "` command chains on every space

**File:** [`CommandLineParser.java`](../../plugins/net.sourceforge.vrapper.core/src/net/sourceforge/vrapper/vim/modes/commandline/CommandLineParser.java#L615-L636) [^src-1]
**Severity:** HIGH (breaks command chaining with arguments)

## Description

In `CommandLineParser.parseAndExecute(String first, String command)`, Ex command chaining checks for `" | "` and then calls `String.split(" | ")`:

```java
if (command.indexOf(" | ") > -1 && ! command.startsWith("com")) {
    String[] commands = command.split(" | ");
    ...
    for (String chainCommand : commands) {
        if ( ! "|".equals(chainCommand)) {
            c = parseAndExecute(first, chainCommand);
```

Because `String.split` takes a regular expression and `|` is the regex alternation operator, `" | "` means `" "` OR `" "` — splitting on **every space** rather than the literal `" | "` separator (leaving `"|"` as a standalone token, which line 623 then tries to ignore).

## Impact

- Any chained command with whitespace arguments fails. For example, `:set ts=4 | set sw=4` splits into `["set", "ts=4", "|", "set", "sw=4"]`, runs `set` with no arguments, and stops or errors on `ts=4`.
- Chained commands are untested in `CommandLineTests.java` [^src-2].

## Suggested fix

- Replace `command.split(" | ")` with `command.split(" \\| ")` (or `Pattern.quote(" | ")`), trim each sub-command, and remove the `"|".equals(chainCommand)` workaround.
- Add regression tests for chained Ex commands (e.g., `:set ts=4 | set sw=4`) and `:s/ | /foo/` fallback in `CommandLineTests.java`.

**Status:** OPEN.
